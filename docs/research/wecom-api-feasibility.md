# 企业微信 API 能力调研：消息接收、媒体与消息发送

调研日期：2026-08-12

## 结论摘要

企业微信可以覆盖部分需求，但不存在一个 API/Bot 形态同时无条件覆盖“普通微信用户、任意单聊、任意群聊、任意媒体、任意主动发送”。可行性取决于会话类型：

| 场景 | 读取消息 | 下载媒体 | 后端主动发送 |
|---|---|---|---|
| 企业内部成员与自建应用单聊 | 可以，配置应用消息回调 | 可以，按回调中的 `MediaId` 下载临时素材 | 可以，应用消息可按成员/部门/标签发送 |
| 企业内部群聊中的经典 Webhook 群机器人 | 不可以；经典 Webhook 是推送入口，不是收消息 Bot | 不可以读取群上传内容 | 可以，但一个 webhook 只对应添加它的那个群 |
| 企业内部群聊中的智能机器人（API 模式） | 可以接收与机器人交互、群内 @ 机器人的消息 | 单聊支持图片、语音、本地文件；群聊触发类型较窄 | 可对触发会话回复；不宜假定可任选任意群主动群发 |
| 企业员工与微信客户/客户群的普通聊天 | 普通“客户联系”API不能实时读取正文；开通“会话内容存档”后可读取存档范围内会话 | 存档消息中的图片/文件等需通过媒体数据接口分片下载 | 不能像普通 IM Bot 一样任意实时私聊/群聊；只能走客户群发等受限制流程，通常需员工确认发送 |
| 微信用户主动进入“微信客服”会话 | 可以，通过客服消息同步/回调接口 | 支持的消息类型可取媒体 | 可以在客服会话与允许的响应时限内由指定客服账号发送 |
| 普通个人微信好友、普通微信群（未通过企微客户联系/客服） | 不可以 | 不可以 | 不可以 |

因此，如果核心产品形态是“用户在群里 @Bot，后端收到文字/PDF并立即自动回复”，建议优先限定为**企业微信内部群 + 智能机器人 API 模式**并先验证 PDF；若必须覆盖含微信客户的外部客户群，则要评估**会话内容存档 + 客户联系群发**，但它并不等价于 Slack/Telegram 式实时 Bot。

## 1. 读取用户或群聊消息

### 自建应用

自建应用开启“接收消息”后，企业微信会把用户发送给应用的消息推送到后端 URL。它适用于企业成员与应用的会话，不代表能监听成员所有私聊或所有群聊。

### 经典群机器人

经典群机器人的官方使用方式是：在某个内部群添加机器人，取得该群专属 webhook，后端向 webhook 发 POST。官方文档只定义了发送和素材上传，没有定义入站消息回调。因此它不能读取群消息，也不能因“有人 @ 它”而获得该消息。它只能向安装它的特定群推送，若要发多个群，需要逐群添加并保存各自 webhook。

### 智能机器人 API 模式

企业微信近年提供智能机器人 API 模式：用户与智能机器人交互时，企业微信向配置 URL 推送消息/事件，可用于内部单聊和内部群中的 @Bot 交互。官方列出的触发范围包括群内 @智能机器人或单聊发送文本、图文混排、引用消息；单聊还支持图片、语音、本地文件。该能力不能被推导为“监听群内全部消息”或“任意选择群主动发消息”。

### 微信客户和客户群

“客户联系”基础 API 可获取客户、客户群及成员等结构化资料，但不能直接读取普通聊天正文。读取员工与微信客户/客户群的聊天内容需采购并开启“会话内容存档”，配置存档成员、IP 和加密公钥，通过 SDK/API 拉取加密消息。存档还受成员范围、客户同意/告知和合规要求约束。

若业务允许把入口改为“微信客服”，微信用户主动进入客服会话后，后端可同步客服消息并回复。这是客服会话，不是读取该用户既有微信好友聊天或微信群。

## 2. 图片、PDF 等媒体

- 自建应用消息回调中，图片、语音、视频、文件等消息会带媒体标识；后端可调用临时素材下载接口。素材有时效，应在收到消息后及时持久化。
- 会话内容存档对图片、文件、语音、视频等返回媒体引用；后端调用“获取媒体数据”，按 `sdkfileid` 等标识分片拉取并自行拼接、落盘。PDF通常作为文件消息处理。
- 微信客服支持的入站媒体按客服消息协议获取。
- 经典群机器人只能由后端先上传文件再发到群里，不能反向读取群成员上传的图片或 PDF。
- 智能机器人 API 模式单聊支持本地文件，因此 PDF 可按文件方向接入；群聊附件不是普遍触发类型，仍需按实际目标场景做媒体矩阵 PoC。

## 3. 向不同群和不同用户发送

### 内部用户

自建应用“发送应用消息”可指定 `touser`、`toparty`、`totag`，但接收对象必须在应用可见范围内。这可以满足向不同企业成员发送通知。

### 内部群

- 经典群机器人：可以向不同内部群发，但每个群要分别添加机器人、持有独立 webhook；并有频率限制。
- 应用群聊 API：可创建/管理特定应用群聊并按 `chatid` 发送，但不等于能向企业里任意已有普通群发消息。
- 智能机器人：适合在触发它的会话内回复，主动任选群发送能力需以当前接口为准。

### 微信客户和客户群

客户联系提供“创建企业群发”等接口，可按客户或客户群创建任务，但这是合规群发流程，不是任意即时发送：存在发送频率、接收次数、群主/发送成员、可见范围及员工确认等限制。若需要真正由后端实时自动回复微信用户，应采用“微信客服”会话，并遵守客服消息响应窗口和账号权限。

## 推荐方案

1. 若对象主要是企业内部员工：采用“智能机器人 API 模式（交互）+ 自建应用（定向通知）”；用 1 天 PoC 验证群 @、图片、PDF 三种入站消息。
2. 若对象是普通微信客户的一对一咨询：采用“微信客服”，这是最接近纯后端客服 Bot 的官方入口。
3. 若必须处理员工与微信客户/客户群的既有聊天：采购“会话内容存档”用于读取和媒体归档，发送端另接“客户联系群发”；接受它无法实现任意、无确认、实时群 Bot 的事实。
4. 不采用个人微信协议逆向、Hook 或模拟客户端方案；它们不属于企业微信官方 API，存在封号、隐私和合规风险。

## 针对“微信用户上传文件，由后端分类并由客服回复”的产品选型

此场景应选 **微信客服 + API 管理模式**，而不是经典群机器人、自建应用或普通企业微信员工账号。

用户通过客服链接、二维码、小程序、公众号、视频号或网页等入口进入一个微信客服会话，在微信客户端内发送文本、图片和文件。企业微信把消息事件通知给后端；后端再调用 `kf/sync_msg` 拉取完整消息，以 `media_id` 下载附件，保存到对象存储，完成病毒扫描、OCR/文本抽取和分类，最后调用微信客服发送消息接口回复该用户。

身份关系如下：

- 用户看到的是企业配置的“微信客服帐号”（可命名为文件助手、资料审核助手等）。
- 它不是可以加入微信群的传统 Bot，也不需要注册一个供程序模拟登录的员工账号。
- 后端应用持有企业微信“微信客服”Secret，并由管理员把该客服帐号设置为 API 管理。
- 业务系统使用 `external_userid`/客服会话标识关联自己的用户和文件任务；不要把微信昵称当稳定主键。

必须提前接受的边界：

- 用户必须先进入客服会话并主动发消息；客服不是能添加任意微信好友的普通帐号。
- 官方客服消息存在响应窗口和发送条数限制。它适合围绕用户咨询或上传任务进行回复，不适合数天后无条件发送营销通知、催办或长期主动推送。
- 若产品必须在任意时间主动触达，需另设计订阅通知、公众号模板/订阅消息，或由企业员工通过客户联系触达；不能仅靠微信客服绕过窗口限制。
- 微信客服是一对一客服会话，不支持加入普通微信群读取群文件。

## 建议 PoC 验收项

- 内部单聊：文本、图片、PDF 的回调与下载。
- 内部群：普通消息是否推送、仅 @Bot 是否推送、机器人回复是否可延迟/主动发送。
- 外部客户群：存档成员与非存档成员组合、客户未同意存档时的行为、媒体下载完整性。
- 发送：不同内部成员、两个内部群、两个客户群；记录频率限制、是否需员工确认、错误码。
- 安全：回调验签与 AES 解密、`corpsecret`/webhook 隔离、媒体及时转存、审计与数据保留策略。
